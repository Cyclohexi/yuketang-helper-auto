# 自动更新与发布

本项目正式发行 Windows x64 ZIP 便携版，通过同目录的 `portable.flag` 启用更新。开发模式及没有便携标记的程序不检查更新。

v2.2.1 起，`userData` 与 `sessionData` 统一固定为 `%LOCALAPPDATA%\YuketangHelper`，与程序更新目录分开；BAT、源码和 EXE 使用同一处。首次启动且固定目录不存在时复制旧 profile，保留旧目录，后续不再覆盖固定数据。`--debug-profile` 使用独立的 `YuketangHelper-debug`，不导入真实配置；`--portable` 不再切换数据位置。v2.2.0 及更早包的数据行为保持不变。

应用就绪 15 秒后检查一次，此后每 6 小时检查一次。顶部版本按钮支持手动检查、下载和重启更新。检查只读取本仓库 GitHub Releases 的最新正式版；不会下载预发布版，也不会降级。下载和重启都由用户点击触发，正在上课时不会自动关闭应用。

## 便携版

读取同一 Release 中的 `update-win32-x64.json`，流式下载其中指定的 ZIP，校验文件大小和 SHA-256。清单只允许指向本仓库同版本的附件。

2026-10-22 修订的 v2.2.1 便携包将更新下载改为每段最多 4 MiB 的 Range 请求，每次从原始 Release 地址获取新重定向；严格核对 `Content-Range` 起止和总大小。服务器忽略 Range 返回 200 时先清空下载缓存再写入，绝不把整包追加到半包后。最终整体 SHA-256 校验不变。原 v2.2.1 及更早包仍使用旧更新器，远程替换附件不会更改已运行的代码；同版本修订需手动下载替换一次，旧版下载失败时也需手动升级。

下载遇到临时网络错误（含 `ERR_HTTP2_PROTOCOL_ERROR`）、断流、HTTP 408/429/5xx 时，连续失败最多额外重试 5 次，间隔 1、2、4、8、15 秒；完成一段后重新计算连续失败次数。单连接 45 秒没有数据会重连，一次下载最长 45 分钟。检查发行信息和清单的临时错误最多额外重试两次；鉴权、无效范围、格式和完整性错误不盲目重试。

下载缓存为用户数据目录下的 `updates/download-<SHA256>.part`，仅同校验值的更新包复用；网络失败及退出应用后保留，重新检查并下载同一版本可续传。失败按钮显示“下载中断 · 继续”，点击直接继续；自动重连时显示保留的百分比。损坏缓存会清除并拒绝安装，磁盘错误不会触发网络重试。下载完毕才复制到隔离安装任务，失败不会关闭正在运行的应用，不影响配置和登录会话。

下载完成后，隐藏的 PowerShell 辅助进程重新校验 ZIP、拒绝路径穿越和携带用户数据的压缩包、预先解压并探测安装目录写入权限。此时主应用仍在运行，安装失败不会提前关闭程序。

同一修订包还包含 Windows 安装交接修复：不用 Node 直接 detached 启动 Windows PowerShell（本机实测会返回成功但不执行脚本），而是通过短时 PowerShell 启动器调用系统 `Start-Process` 创建独立安装进程。主进程核对安装器写入的 `ready.json` 中任务 ID 和 PID，最多等待 15 秒，确认就绪后才关闭应用。启动器失败或未就绪时保留应用并显示错误。回归测试包含真实调用进程退出后的安装，不仅测试 `parentPid=0` 的文件替换。

安装记录保存在 `updates/installer-<任务ID>.log`；启动失败信息在对应任务的 `launch-error.log`，启动器返回信息在 `launch.log`。成功替换后先移除该任务的临时文件再启动新程序，避免首次迁移复制与任务清理竞态；新程序使用正常窗口方式启动。诊断日志仅记录安装阶段、程序路径和错误，不记录登录或 AI 凭据。原 v2.2.1 及更早包不包含此修复。

用户确认重启后，辅助进程等待应用退出，只替换 Electron 程序目录及文件，不触及固定用户数据目录，并继续保留程序旁旧的 `ykt-helper-data`、个人文件及其他目录。被替换的程序文件先备份；普通复制失败时回滚并重新启动旧版本。更新结果写入用户数据下的 `updates/result.json`，下次启动可读取。突然断电、磁盘损坏或回滚本身失败仍需人工从 `.ykt-update-backup-*` 恢复，不能保证这些情况下自动恢复。

重命名为“雨课堂助手.exe”的便携版也保留原可执行文件名。只读目录、受管控禁止 PowerShell 的设备会提示失败，可重新检查后重试或手动更新。需要能够访问 GitHub API 及附件下载域名；不引入第三方下载镜像。

## 发布步骤

README 更新记录、根 changelog、GitHub Release 及应用更新说明只展示本次计划进入便携版的重要用户功能、明显修复和必要升级提示。不得直接汇总全部 Git 提交；源码 BAT、个人调试、清理、项目记忆、同步检查等维护变化不作为公开条目，详见[项目维护规则](project-maintenance.md)。v2.2.1 展示题目预分析及相关提醒、AI 请求失败自动重试、截止未提交自动强制补交三个功能与独立开关，并按最新授权增加一条自动更新修复。技术细节与开发记录保留在开发文档中。

先按[项目维护清单](project-maintenance.md)同步代码与文档，再在 `ykt-helper-win` 下运行。所有工作区包和锁文件采用同一个稳定版本号。默认新版本递增；仅本次用户于 2026-10-22 明确要求同版本修订，保持 2.2.1，先备份原附件和标签信息，再核对新包与当前源码、标签一致并替换附件。已安装原 2.2.1 的用户须手动替换。以下为本次版本命令，后续版本恢复递增：

```powershell
npm run version:set -- 2.2.1
```

构建、检查并生成便携发行包：

```powershell
npm ci --include=dev --include=optional
npm run sync:check
npm test
npm run lint
npm run prepare:desktop
npm run make:portable -w yuketang-helper-desktop-package
npm run release:prepare
```

最后一步将当前版本的以下两个文件统一放入 `desktop/out/release/v<版本>/`，并生成 ZIP 的大小和 SHA-256 校验信息：

- `YuketangHelper-v<版本>-Windows-x64-Portable.zip`
- `update-win32-x64.json`

确认代码及版本号后提交，并将对应的 `v<版本>` 标签推送到远程。为每次发布编写 `docs/release-notes-v<版本>.md`，并同步 README 的“版本更新记录”。`npm run release:upload` 使用 `GH_TOKEN` / `GITHUB_TOKEN` 或 Git 凭据，将两个文件上传到 **Release 草稿**。上传后核对 GitHub 返回的 SHA-256 和大小，只有两个附件均通过校验才可发布；上传中断时可重试并复用已校验的附件。

从已验收的固定提交构建，确认编译产物与该提交一致。Git 回退只恢复源码，不恢复数据库；测试和旧版复现使用独立 profile 或数据备份，不用旧数据库假设覆盖新数据。

默认创建草稿；明确执行 `npm run release:upload -- --publish` 时，完整上传并校验后才公开发行。脚本不会删除或覆盖已有公开版本，且拒绝发布含其他附件的草稿。

本次同版本修订不使用普通上传脚本覆盖检查，也不永久放宽该检查。单次维护先将原附件及公开元数据、标签信息备份到 `desktop/out/release-backups/v2.2.1-original-20261022/`，完整构建新包并计算摘要，再替换附件、同步说明和标签，核对 GitHub 两个附件的大小与 SHA-256。远端只保留正式 ZIP 与清单，不上传测试包。旧版本的运行代码不会因附件替换而自行修复，手动升级提示必须同时出现在 README、changelog 与 Release 说明中。

旧的 2.1.0 及更早程序没有更新代码，需要用户手动替换一次含此功能的便携版；此后可以在应用内更新。旧版 Release 缺少更新清单时，不会被当作有效的便携版更新。

## 验证范围

契约测试覆盖版本比较、同源附件约束、重复操作、网络错误、下载校验、便携更新状态和界面交互。Windows 测试实际执行 PowerShell，验证中文与引号路径、改名程序、用户数据保留、复制失败回滚和危险压缩路径。真实的“旧便携版 → GitHub 新版”升级仍应在发布草稿前，使用隔离测试目录和测试发行源验证。

参考：[Electron 更新说明](https://www.electronjs.org/docs/latest/tutorial/updates)。
