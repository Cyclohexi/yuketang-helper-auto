# 课堂 AI 自动化与提醒

本说明对应当前源码，计划随 v2.2.1 发布，等待用户测试确认；尚未包含在已发布的 v2.2.0 便携包中。

## 使用流程

1. 配置可用的 AI 模型并进入课堂，在设置中开启“LLM 自动生成”。
2. 开启“题目预分析”后，当前课堂题目加载即分析，包括未开放题目；关闭后等待老师发布再分析。开始提示“AI 分析题目中，共 N 道题”，完成提示“AI 分析了 N 道题”，并显示成功、失败数量。
3. 老师发布题目后，只有开启“LLM 托管提交”才自动使用缓存答案作答；如果分析尚未结束，等待结果并复核截止时间。原生成延迟现在表示发布后提交延迟，随机延迟同样用于提交。
4. 开启“AI 请求失败自动重试”后，临时网络、超时及 HTTP 408/429/5xx 在 1 秒、2 秒后最多额外重试两次，适用于分析、OCR 和翻译。密钥、参数、答案格式和主动取消不自动重试；重试使用同一请求和对话上下文。
5. 开启“截止未提交时自动强制补交”后，活动课堂中已截止的未作答题会使用缓存 AI 答案尝试 `forceRetry`；没有分析结果时先分析。仍需开启自动生成及托管提交，每题每次应用会话自动尝试一次，不无限重试被拒绝的补交。
6. 平台接受提交或补交后提示“作答成功”；没有可用答案、截止且未开启补交、平台拒绝提交时提示“作答失败”。成功表示平台接受提交，不表示答案一定正确。

三个功能在设置中独立保存。预分析默认开启以兼容此前源码，自动重试与自动补交默认关闭。关闭托管仍可分析，关闭自动生成停止安排后续自动提交；关闭补交时不再安排到期题目提交。提醒开关只控制提示。课堂结束、题目已作答或切换课堂时不继续安排补交。题目没有提前获取到时只能在实际加载后分析；重试次数用尽后不会每秒重新调用模型，可在 AI 页手动重试。已发出的模型和提交请求不能撤回。

## 提醒设置

保留新题开始、考试与题组、新课件、课堂开始、课堂结束；新增 AI 分析开始、AI 分析完成、作答成功、作答失败。其他发布与旧 Agent 排队/开始/提交/失败提醒已移除。

九项事件均可在设置中单独开关，另保留提醒总开关、系统通知、页面弹窗、声音与提示音设置。旧版 Agent 开始偏好迁移到分析开始，Agent 成功偏好迁移到分析完成及作答成功，Agent 失败偏好迁移到作答失败；已保存的新开关优先。课堂开始在首次连接活动课堂或收到开始事件时提示，同一课堂重连不重复提示。

## 维护约束

- `apps/desktop/renderer/src/classroom-preanalysis.ts` 只负责分析队列与当前会话缓存，不提交答案。每批新增题目独立统计，最多两路模型请求，单题失败不阻塞其他题；缓存不跨应用重启保留。
- 缓存按环境、课堂、模型配置、预分析模式以及题型、题干、选项、填空与课件图片区分；仅发布状态改变不会重新请求模型。题目或图片内容改变时重新分析，批次中被替换或移除的任务按失败统计。关闭预分析时不纳入 locked 题目，开启托管及自动补交时才纳入 expired 题目。
- `AssistantPanel.vue` 在加载后启动预分析，在题目开放后安排提交；同一题不重复安排正在进行的提交。切换课堂、环境、模型及关闭自动生成时丢弃旧结果；关闭托管或课堂结束时取消后续自动提交。已发送的模型请求或提交请求无法撤回。
- 提交前检查当前题目状态、课堂、开关与截止时间；Backend 同时阻止 Agent 提交未发布、已作答或结束课堂的题目；关闭自动补交时也阻止隐式到期重试，包括刷新 token 期间越过截止时间的情况。手动作答与既有补交流程保持原有规则。
- `packages/backend/src/llm/request-retry.ts` 在模型请求层实现有限重试，不重复创建答案或追加对话消息。等待期间再次检查开关及模型配置，支持 AbortSignal 取消，最终只返回一次结果并计入一次分析统计。
- `apps/desktop/main/ai-image-preparation.ts` 在调用模型前，对课件图片读取的临时网络和超时错误使用相同开关和重试上限；HTTPS、图片类型及 16 MiB 限制保持不变。图片读取与模型请求分别处理，不通过外层重复执行已完成的模型调用。
- `ClassroomNoticeKind` 与设置契约、后端课堂事件、前端事件筛选和 SQLite 偏好迁移须一起维护。通知投递失败不改变提交的成功状态。

对应测试为 `tests/contract/classroom-preanalysis.test.ts`、`tests/contract/ai-automation.test.ts`、`tests/contract/ai-image-preparation.test.ts`、Backend 的 `llm/request-retry.test.ts`、`ai-retry.test.ts`、课堂生命周期与 M6 测试、Storage M5 测试。使用模拟模型和课堂数据，验证时不连接真实模型服务或提交真实课堂答案。
